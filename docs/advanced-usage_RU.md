# Расширенное использование

[English](advanced-usage.md) | Русский · [К быстрому старту](../README_RU.md)

Для повседневной работы достаточно `mojilex`. Здесь описаны отдельные этапы
обработки, автоматизация, локальные снимки базы и обслуживание репозитория.
Заменяйте `NewsEmoji` названием своего пака; `mojilex list` показывает доступные
имена и сохранённые запуски.

## Отдельное скачивание, анализ и публикация

```console
mojilex import "https://t.me/addemoji/NewsEmoji"
mojilex describe NewsEmoji --ai-concurrency 4
mojilex show NewsEmoji
mojilex publish NewsEmoji --local
mojilex publish NewsEmoji
```

`import` скачивает и проверяет медиа. `describe` создаёт сохранённый локальный
черновик. `publish --local` проверяет готовый черновик без отправки; `publish`
создаёт или обновляет Pull Request на GitHub без повторного AI-анализа.

Старые сохранённые описания остаются совместимыми. При записи база переходит
на имена файлов с 8 символами хеша; повторный анализ для этого не нужен.
Если после публикации изменится `main`, включённый в репозитории процесс
**Refresh open data PRs** обновит PR из ветки этого же репозитория и запустит
проверки. Для PR из форка повторите `mojilex publish NewsEmoji`. Если обе стороны
изменили одну запись по-разному, потребуется разрешить конфликт этой записи.

`show` выбирает готовые описания, `publish` — завершённый черновик, а `resume` —
последний незавершённый запуск. Если имя относится к нескольким репозиториям или
группам источников, укажите точный Run ID из `list`.

Для скриптов поддерживается прежний сценарий с Run ID:

```console
mojilex describe mlxrun_YOUR_ID
mojilex submit mlxrun_YOUR_ID --publish local
mojilex submit mlxrun_YOUR_ID --publish pr
```

`describe` также может продолжить запуск `add` до начала публикации, сохранив
его идентификатор, готовые описания и расход бюджета. Запуск с контрольной точкой
публикации нельзя преобразовать в другой сценарий.

Прямая команда `add` объединяет анализ и настроенный режим публикации.
Указывайте `--publish local`, если отправлять данные на GitHub не нужно.
Для проверки медиа без запросов к AI и сохраняемого поэтапного запуска:

```console
mojilex add "https://t.me/addemoji/NewsEmoji" --dry-run --check-media
```

## Продолжение, скорость и лимит запросов

```console
mojilex resume NewsEmoji --download-concurrency 8 --ai-concurrency 4
```

Параллельность ИИ, скачиваний, декодеров и паков принимает любое целое число
от 1, без фиксированной верхней границы. По умолчанию
`processing.performance_mode = "auto"`: при старте операции параллельность
подбирается по процессору и свободной памяти, более высокие заданные значения
сохраняются. Режим `manual` использует четыре заданных значения точно.
Автоматический ориентир: один декодер на логический процессор, но не более
75% свободной памяти из расчёта 512 МиБ на декодер; вдвое больше подготавливаемых
паков, четыре скачивания и два запроса ИИ на логический процессор.
Это стартовый расчёт, а не гарантия роста скорости при повышении параллельности.
Автоматический бюджет временных файлов увеличивается до двукратного объёма
свободной RAM, но не превышает четверти свободного места на временном диске.
Если объём памяти или диска определить не удалось, бюджет не увеличивается.
В ручном режиме остаётся заданный бюджет временных файлов. Повышение параллельности требует больше памяти и CPU;
скорость также зависит от квот и времени ответа провайдера. Лимиты запросов и
стоимости при этом не растут. Настройки будущих запусков меняются в
`mojilex settings`.

`processing.file_analysis_mode` задаёт режим файла с несколькими паками: `fast`
готовит следующие паки параллельно с упорядоченным анализом ИИ; `sequential`
полностью заканчивает один пак; `download_all` сначала сохраняет все оригиналы;
`prepare_all` параллельно скачивает и декодирует все паки до запросов к ИИ.

По умолчанию бюджет — **100 AI-запросов на весь запуск**, включая повторы,
восстановление по одному эмодзи и необязательный переход к другой модели.
`resume` сохраняет расход. Попадания в кеш не требуют запросов. Для нового
запуска `add` доступны `--max-ai-requests` и `--max-cost-usd`; продолжение не
обнуляет бюджет.

При временных обрывах Telegram по умолчанию делает до 6 попыток
(`telegram.max_attempts`: 1–8). Прерванное скачивание начинается со свежего
буфера ограниченного размера. Для временных сбоев Gemini предусмотрено до
3 попыток с паузами 1 и 2 секунды; каждая учитывается в бюджете и имеет тайм-аут
30 секунд. Ошибки авторизации и обычные некорректные запросы не повторяются.

Некорректные ответы AI и исчерпанные сетевые повторы откладывают незавершённые
эмодзи, пока оставшаяся AI-очередь продолжает работу. Затем программа повторяет
их по одному в пределах общего бюджета. Каждый проверенный результат сразу
сохраняется. Лимит запросов или стоимости, отказ в разрешении, ошибка авторизации
или сохранения и отмена останавливают очередь; успешные активные пачки всё ещё
сохраняют результат. Ошибки медиа после допустимых повторов останавливают очередь
медиа, а активные задачи безопасно завершаются. При продолжении проверяются
идентичность источника и хеши сохранённых кадров; готовое используется повторно,
отсутствующие или повреждённые кадры при необходимости создаются заново.

Если цена модели неизвестна, интерактивное разрешение охватывает остаток лимита
для текущего вызова команды, включая повторы. Лимит не увеличивается; следующий
`resume` спрашивает снова. Флаг `--allow-unknown-cost`, где он поддерживается,
задаёт явное согласие. Без него автоматизация останавливается, если такого
разрешения нет. Работа только с кешем не требует согласия на расходы.

Для измеримой работы показывается число готовых элементов; для ожидания —
анимация, текущий этап и прошедшее время. Время ожидания не считается выполненной
работой. Вопросы приостанавливают перерисовку. Прогресс выводится в stderr, в том
числе с `--json`; `--quiet` скрывает его.

## Локальное хранение и ключи

Исходные скачанные файлы и листы кадров временные. Выбранные PNG-кадры сохраняются
локально в `resume-media` внутри настроенной папки кеша, вне базы данных, для
продолжения и превью галереи. Они делят дисковый бюджет запуска с временными
файлами. Очистка метаданных через `cache prune` не удаляет эти папки кадров.
Для старого запуска, кадры которого уже удалены, может потребоваться один проход
рендеринга; галерея показывает заглушку, если превью недоступно.

Исходные медиа, сохранённые кадры, листы кадров, ключи и ссылки скачивания Telegram
никогда не коммитятся в базу. Просмотр описаний и галереи не обращается к AI и не
скачивает медиа. Права на медиа Telegram принадлежат соответствующим владельцам.

Приоритет настроек: **командная строка → переменные окружения → проектный
`.mojilex.toml` → пользовательская конфигурация → значения по умолчанию**.
`mojilex config show` показывает итоговые несекретные настройки. `settings`
меняет значение в проектном файле, если оно определено там, иначе — в
пользовательском. Настройки прошлых запусков сохраняются; переменные окружения
остаются приоритетнее.

Пример проектной конфигурации; укажите выбранный вами идентификатор модели:

```toml
[repository]
target = "MojiLex/mojilex"
base_branch = "main"
publish = "pr"

[telegram]
timeout_seconds = 30
download_concurrency = 4
max_attempts = 6

[ai]
provider = "gemini"
model = "YOUR_MODEL_ID"
languages = ["ru", "en"]
max_ai_requests = 100
ai_concurrency = 1
model_routing = "off"

[dedupe]
mode = "exact"
profile = "dedupe-v1"
max_candidates = 20

[processing]
file_analysis_mode = "fast"
pack_concurrency = 3
render_concurrency = 2
static_batch_size = 16
animated_batch_size = 8
keyframes = 8
render_timeout_seconds = 15
```

Среди переменных окружения: `MOJILEX_MODEL`, `MOJILEX_AI_CONCURRENCY`,
`MOJILEX_DOWNLOAD_CONCURRENCY`, `MOJILEX_MAX_AI_REQUESTS`, `MOJILEX_MAX_COST_USD`,
`MOJILEX_FILE_ANALYSIS_MODE`, `MOJILEX_REPO`, `MOJILEX_CACHE_DIR` и
`MOJILEX_RUNS_DIR`.
`mojilex config set-ui-language ru` меняет только сохранённый язык интерфейса;
`MOJILEX_UI_LANGUAGE` временно его переопределяет. Новый язык действует со
следующего вызова. Команды, флаги и поля JSON остаются английскими.

`init` записывает несекретные настройки. `config set-credentials` запрашивает
ключи скрытым вводом и сохраняет их в системном хранилище; `config clear-credentials`
удаляет их. Без сохранённых ключей интерактивный анализ запросит недостающие
значения только для текущего процесса. Окружение имеет приоритет над системным
хранилищем. Если хранилище недоступно, сохранение завершается ошибкой без записи
секретов в конфигурацию.

Для JSON, тихого режима, перенаправленного ввода и неинтерактивных запусков
используйте сохранённые ключи или переменные процесса `TELEGRAM_BOT_TOKEN` и
`GEMINI_API_KEY`. Обычная публикация использует вход через `gh auth login`;
для автоматизации также доступны `GH_TOKEN` и `GITHUB_TOKEN`. Не записывайте
эти значения в TOML или Git.

## Публикация и необязательная проверка

Pull Request предлагает включить данные в базу; его создание ещё не означает
слияние. Перед отправкой CLI проверяет всю базу. Единица публикации — коллекция:
одна повреждённая запись не позволяет опубликовать часть пака. Предупреждения
и категории контента остаются в записях и **никогда не требуют одобрения и не
блокируют публикацию**. Отсутствие квалификации модели не требует ручной проверки;
указанные метаданные квалификации и структура записей всё ещё проверяются.

`review NewsEmoji` остаётся совместимой командой просмотра. Явная команда
`review EMOJI_ID approve|request-changes|reject` записывает необязательное
редакторское решение. `dedupe review` — отдельное решение о связи двух эмодзи.
Похожесть никогда не объединяет платформенные ID автоматически. Подробнее:
[Анализ дублей и проверка](dedupe-and-review.md).

Прямой push предназначен для владельца репозитория:

```console
mojilex submit mlxrun_YOUR_ID --direct-push
```

Он требует прав записи и обхода правил ветки, валидации, успешных обязательных
проверок точного коммита, неизменившейся основной ветки и подтверждения итогового
коммита и путей. CLI не делает force push и не ослабляет правила GitHub.
Подробнее: [Публикация](publishing.md) и [Модель безопасности](security-model.md).

## Офлайн-снимки базы

Сохранённый черновик пака и снимок выпуска — разные вещи. `mojilex snapshots`
показывает существующие снимки рядом с текущей папкой и настроенным локальным
репозиторием данных, включая `dist`, `snapshots`, `releases` и один уровень
вложенных папок. Весь диск не сканируется, выпуски не скачиваются. Если снимок
один, команды чтения выбирают его автоматически; иначе укажите `--snapshot PATH`.
`MOJILEX_SNAPSHOT` закрепляет существующий снимок и ограничивает список этим путём.

```console
mojilex snapshots
mojilex snapshot verify PATH
mojilex search "celebration" --snapshot PATH --view search --allow-unverified
mojilex get TELEGRAM_CUSTOM_EMOJI_ID --snapshot PATH --allow-unverified
```

`get` принимает точный числовой ID кастомного эмодзи Telegram или канонический
`mxe_...` и требует однозначного текущего соответствия. `search` также распознаёт
точные платформенные ID. Чтение работает офлайн, не обращаясь к Telegram, AI,
декодерам или каталогу.

В MVP снимок `distribution-v1` проверяется на целостность, но не подписан.
Для его чтения нужно явное диагностическое согласие `--allow-unverified`; оно
не делает выпуск доверенным, а `runtime_trust.safe_eligible` остаётся false.
Поэтому представление `agent` по умолчанию может быть пустым даже с этим флагом.
Для диагностического поиска явно выбирайте `search` или `canonical`.
Проверка подписанных каталогов, отзывы выпусков, аттестации, разделённые выпуски
и дельты пока запланированы на будущее.

## Справочник команд

Полный список: `mojilex --help-all`; точные параметры: `mojilex COMMAND --help`.

| Задача | Команды |
| --- | --- |
| Повседневная работа | `list`, `show`, `gallery`, `settings`, `publish`, `resume` |
| Импорт и анализ | `add`, `import`, `describe`, `update SOURCE\|COLLECTION_ID\|--all` |
| Обслуживание репозитория | `validate [PATH]`, `submit [PATH\|RUN_ID]`, `build-index [PATH]` |
| Связи дублей | `dedupe scan`, `dedupe explain`, `dedupe review` |
| Редакторские операции | `review`, `set-status`, `takedown` |
| Бенчмарки | `benchmark-dedupe`, `benchmark-model` |
| Настройка и диагностика | `init`, `doctor`, `config show`, `config set-ui-language` |
| Сохранённые ключи | `config set-credentials`, `config clear-credentials` |
| Кеш | `cache info`, `cache prune` |
| Офлайн-данные | `snapshots`, `snapshot verify`, `search`, `get`, `get-collection`, `resolve`, `similar` |
| Удаление | `uninstall` |

С `--json` stdout содержит один машиночитаемый объект-обёртку. Диагностика
и прогресс идут в stderr. Для скриптов см. [Коды ошибок и выхода](error-reference.md),
для оценочных запусков — [Бенчмарки](benchmarks.md).

## Устранение проблем и удаление

Если не хватает компонентов медиа, запустите `mojilex doctor`; смотрите значение
`ready`, а не только успешное завершение диагностики. На поддерживаемых Windows
команда `doctor --install` устанавливает недостающие компоненты FFmpeg или TGS.
TGS требует адаптер без потерь `mojilex-rlottie-rgba`; исходная утилита `lottie2gif`
не поддерживается. См. [Компоненты медиа](media-prerequisites.md), затем продолжите
существующий пак вместо повторного импорта.

Если старая конфигурация указывает на несуществующий локальный репозиторий,
проверьте `config show` и исправьте `repository.target` в соответствующем файле.
Только если вы намеренно хотите заменить старую несекретную пользовательскую
конфигурацию, сохраните её копию и выполните
`mojilex init --force --repo MojiLex/mojilex --publish local`.
Это замена конфигурации, а не универсальная команда восстановления.

Чтобы удалить установленную программу, сохранив настройки, запуски, кеш и ключи:

```console
mojilex uninstall --keep-data
```

Без `--keep-data` подтверждённое удаление также убирает стандартные данные MojiLex,
сохранённые ключи и его TGS-адаптер. Перед подтверждением команда показывает точные
цели. Общие установки `uv`, Git, FFmpeg и Visual Studio сохраняются.
